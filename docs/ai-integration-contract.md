# AI 연동 준비: 입력과 근거의 경계

이 문서는 저장된 데이터와 AI 연동의 검증 경계를 정리한 자료다. 현재 Gemini 기반 수강 후보 API가 구현되어 있으며 요청·응답과 실행 방법은 [README](../README.md#gemini-수강-후보)를 참고한다. 문서 분석 작업·항목·확인 답변, 전체 로드맵 실행·결과 저장, A26/A27은 아직 구현되어 있지 않다. 아래의 그 외 스냅샷과 수신 검증은 향후 구현 조건이다.

## 계획과 입력 버전

| 논의할 정보 | 현재 출처와 의미 |
|---|---|
| 계획 ID | `roadmap_inputs.request_id`. 계획의 소유자는 서버가 검증한 `session_owners.owner_id`로 결정한다. 사용자가 지정한 소유자 ID는 신뢰하지 않는다. |
| 전체 입력 버전 | `roadmap_inputs.input_revision`. 실제 기본 정보·과목 선택·목록 확인·문서 등록/삭제/추출 완료/부분 확인 등 분석 입력이 바뀌면 증가한다. 입력이 바뀌지 않은 재저장은 증가하지 않는다. |
| 입력 기준 | AI에 전달할 때는 서버가 소유권을 확인하고 DB의 같은 읽기 시점에서 입력과 근거 버전을 고정해야 한다. 입력 버전과 현재 버전이 다르면 오래된 결과를 현재 입력의 결과로 표시하지 않는다. |

문서 파싱은 비동기다. 화면에서 본 revision을 확인한 후에도 문서 상태가 바뀔 수 있으므로 향후 작업 접수 시와 결과 저장 시 유효성을 다시 검사해야 한다. 스냅샷 저장과 생성 실행은 아직 없다. 세션 토큰과 다른 사용자의 입력을 AI 입력으로 전달하지 않는다.

## 사용자가 제공한 기본 정보

`roadmap_inputs`의 `career_goal`, 선택 `target_role`, `university_id`, `department_id`, `catalog_id`, `year_level`, 선택 `earned_credits`, `gpa`, `gpa_scale`이 현재 값이다. 학교·학과 명칭과 지원 여부는 각 기준 테이블에서 ID로 연결한다.

- 목표는 분석 실행에 필수이며 빈 초안에는 없을 수 있다. 희망 직무가 없으면 목표에서 특정 직무를 확정하지 않는다.
- 숫자 미입력 `NULL`과 실제 `0`은 다르다. GPA는 만점과 함께 해석하며 취득학점과 과목 선택 합계를 혼동하지 않는다.
- 기준 목록이 없거나 미지원인 경우 그 사실을 제한으로 보존한다. 현재 제공된 학교·학과·과목은 실제 교육과정이 아닌 개발용 fixture다.

## 과목 목록과 사용자 선택

`course_catalogs`의 `catalog_id`, `version_label`, `scope_description`, `completeness_status`, `source_name`, `source_url`, `retrieved_at`, `curriculum_year`가 목록의 기준과 출처다. 학년만으로 교육과정 연도를 추정하지 않는다. `catalog_courses`의 `course_id`, 목록 기준 이름·코드·학점·구분·권장 학년/학기는 표시 정보이며 실제 개설 여부와 다르다.

`input_course_states`는 요청과 과목 ID별 사용자의 이수 신고와 `source_catalog_id`를 보관한다. 현재 목록 안의 true 선택, 현재 목록 밖에 보존된 true 선택, OFF 또는 행 없음은 각각 구분한다. 같은 이름만으로 과목 ID를 합치지 않는다. 이수 선택은 학교의 공식 학적 검증이나 기술 숙련도 증명이 아니다.

`course_selection_revision`과 `reviewed_catalog_id`, `reviewed_selection_revision`, `reviewed_at`, `reported_missing_courses`를 함께 사용한다. 유효한 목록 확인은 현재 목록 ID와 선택 버전이 확인 값과 일치하고 확인 시각이 있어야 한다. 사용자 확인 상태는 다음과 같다.

- `unavailable`: 현재 목록 없음. 선택 0개로 해석하지 않는다.
- `unconfirmed`: 목록 또는 현재 선택에 대한 유효한 확인이 없음. OFF를 미이수로 확정하지 않는다.
- `confirmed`: 현재 목록 전체를 확인했고 누락 신고가 없음. 0개 선택도 가능하다.
- `partial`: 현재 목록 전체를 확인했으나 목록에 없는 이수 과목을 신고함.

원천의 `completeness_status`와 사용자의 확인 상태는 서로 다른 정보다. 검색 결과나 한 페이지만 전체 목록으로 취급하지 않으며, 목록 밖 과목을 현재 목록의 미이수로 추정하지 않는다.

## 문서와 읽힌 원문

`project_documents`에서 현재 계획에 속하고 `removed_at`이 없는 문서의 `document_id`, `extraction_revision`, `extraction_status`, `partial_confirmed_at`을 확인한다. `document_extractions`에서 정확히 `(document_id, extraction_revision)`에 해당하는 `extracted_text`, `segments`, `limitations`, 상태와 오류를 읽는다. 원본 파일은 비공개 저장소에 있으며 저장 키는 사용자 소유권을 대신하지 않는다.

분석 가능한 문서는 `ready` 또는 **현재 추출 버전**을 사용자가 확인한 `partial`이다. `pending`, `failed`, `needs_ocr`, 확인하지 않은 `partial`, 삭제된 문서는 분석 근거로 포함하지 않는다. 일부 추출은 읽힌 범위만 포함한다. 재추출은 새 버전이며 이전 부분 확인은 해제된다. 실제 텍스트가 없거나 파일이 있다는 사실만으로 경험·역량을 생성하지 않는다.

각 segment는 본문에서 `start` 이상 `end` 미만인 문자 범위와 가능한 `page` 또는 `paragraph`를 제공한다. 현재 문자 위치는 Python 문자열의 유니코드 코드 포인트 기준이며 바이트 또는 JavaScript UTF-16 위치와 같다고 가정하면 안 된다. 현재 문서 segment에는 별도 segment ID가 없으므로, 향후 식별 방법은 담당자 협의가 필요하다. 반환된 구절은 지정 문서·추출 버전의 실제 본문 범위와 일치해야 한다. 텍스트와 위치가 없는 이미지 내용은 추측하지 않는다.

삭제는 현재 입력에서 즉시 제외하고 원본·모든 추출 버전을 정리한다. 향후 스냅샷·결과 근거에 대해서도 삭제 정책을 적용해야 하며 이전 결과를 이용해 삭제된 문서를 우회 조회해서는 안 된다. 현재 과거 결과 스냅샷은 존재하지 않는다.

## 외부 자료와 상태

`external_sources`의 출처 ID·이름·종류·`source_environment`, `external_collection_jobs`의 작업 범위·상태·coverage·시도·건수, `external_items`의 출처별 원문 ID·URL·최신 관측과 확인 시각, `external_item_versions`의 버전 ID·원문 바이트/hash·본문·`segments`·`source_facts`·`recruitment_facts`·제한·수집 시각이 별도로 보관된다.

- `source_environment=fixture`인 자료는 가상 검증 데이터다. 실제 공고나 운영 출처로 제시하거나 실제 사용자 추천 근거로 자동 사용하지 않는다. 현재 실제 출처·실수집 자료는 없다.
- 외부 `segment_id`는 해당 `item_version_id` 안의 구절에만 유효하다. 원문 필수·우대 기술, 활동 내용·제출물·참가 조건은 각 공고에서 명시된 그대로 구분한다. 하나의 공고를 직무 전체의 필수 조건으로 일반화하지 않는다.
- `succeeded`와 완전한 확인 범위에서 발견 0건, `partial`, `failed`, 미실행·미확인은 서로 다르다. PDF fixture는 원문을 확보해도 항목 미분류로 부분 처리될 수 있다. 모집 상태 `open`/`closed`/`unknown`은 저장된 관측이며 실패 후 과거 상태를 현재 확인된 사실로 표시하지 않는다.
- 최초 버전의 수집·확인 시각과 `external_items.last_confirmed_at`의 후속 확인은 구분한다. 수집 실패는 마지막 성공 확인 시각을 갱신하지 않는다. 마감 시각·시간대·참가 자격이 불명확하면 채우지 않는다.
- 외부 자료 갱신은 개인 `input_revision`을 바꾸지 않는다. 향후 결과를 만들 때 실제로 선택한 자료 버전과 상태를 별도로 고정해야 한다. 현재 `run_external_items`와 결과 실행은 미구현이다.

## 향후 수신 결과의 서버 검증 경계

다음은 스키마 확정이 아니라 담당자와 합의할 때 유지해야 할 관계다.

1. 현재 세션 소유자 → `request_id` → 해당 입력 스냅샷의 revision을 검증한다. 사용자가 임의로 보낸 owner ID나 다른 계획의 ID를 신뢰하지 않는다.
2. 문서 근거는 같은 계획의 삭제되지 않은 문서·전달한 추출 버전·실제 본문 위치에 속해야 한다. 부분 확인이 필요한 경우 그 버전의 확인 상태를 검사한다. 재추출·삭제 후에는 오래된 근거의 유효성을 다시 확인한다.
3. 과목 참조는 고정한 목록의 실제 `course_id`와 소속을 확인하고, 이미 이수한 선택과 현재 목록 밖 이력을 구분한다. 후보·결과의 중복 여부와 제한 상태는 서버가 확인한다.
4. 외부 근거는 해당 실행에 서버가 실제로 고정한 `item_version_id`와 그 버전의 `segment_id`에 속해야 한다. 버전 ID만으로 다른 실행의 자료를 조회하지 않는다. 당시 자료와 현재 확인 상태는 별도로 표시한다.
5. 응답이 미확인·무응답·명시적 경험 없음·부분 자료·실패를 임의로 같은 상태로 바꾸거나, 문서 존재·이수 선택만으로 숙련도를 확정하지 않도록 검증한다. 해당 표현과 오류 처리의 구체 형식은 협의가 필요하다.
6. 원문은 인용 대상 데이터이며 실행 지시가 아니다. 입력 변경이나 문서 삭제가 발생한 경우 결과 수신과 저장의 경쟁 상태를 검증하고, 외부 모델이 반환한 식별자·URL·텍스트를 그대로 신뢰하지 않는다.

모델 공급자와 데이터 전송 범위, 비동기 작업·실패·재시도 방식, 구체 요청/응답 형식, 결과 이력과 삭제 정책은 AI 담당자 및 서비스 설계자와 협의해야 한다.
